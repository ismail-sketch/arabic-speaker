# AGENTS.md — Arabic Speaker (тренажёр арабского в фусха)

Голосовой тренажёр разговорного **литературного арабского (MSA/фусха)**: пользователь говорит
в микрофон, приложение отвечает голосом и текстом, показывает перевод и исправляет ошибки.

## Стек и структура

- **Бэкенд:** `server.js` — Node.js (без зависимостей), локальный прокси к AnyModel
  (OpenAI-совместимый API) + раздача статики. Ключ в `.env` (не в git).
- **Фронтенд:** `index.html` — один файл: HTML + CSS + JS inline.
  TTS — встроенный Web Speech API. STT — браузерный (Chrome/Edge) или серверный.
- Слои: `index.html` (UI/речь) → `/api/chat`, `/api/transcribe` (server.js) → AnyModel.

## Запуск

```
cp .env.example .env   # вписать ANYMODEL_KEY
node server.js         # http://localhost:8787/
```

Модель по умолчанию `gc/gemini-2.5-flash` (быстрая, ~1 c). См. `server.js` (MODEL) и `.env.example`.
Серверное распознавание использует `MODEL_TRANSCRIBE` (`gc/gemini-3.1-flash-lite-preview`).

## Что уже сделано

- Голосовой диалог: STT `ar-SA/+fallback`, TTS, текстовый ввод.
- Push-to-talk: накопление всего распознанного (в т.ч. промежуточного), паузы не обрывают запись.
- Разбор ошибок по категориям (грамматика/лексика/предлоги и т.д.) + «✓ Отлично!».
- Переключатель огласовок (харакат) в настройках и в чате (сохранение в localStorage).
- Диагностика «Проверить микрофон», выбор голоса, уровень/тема, история диалога.
- Смешанный режим AR+RU: русский вопрос «как сказать…?» → арабская фраза, перевод и
  короткое пояснение; переключатель языка микрофона ар/рус (кнопка «Язык: ар/рус»).
- Смешанная фраза на ходу: язык можно переключать прямо во время записи — сказанное
  не теряется, а дописывается на другом языке в одно сообщение; после отправки язык
  возвращается к тому, с которого начали.
- Итог занятия при «Завершить»: ошибки из FIX, фразы, о которых переспрашивал, слова;
  кнопка «Улучшить разбор ИИ» (строгий JSON), экспорт в `.md`.
- История последних 20 занятий и общий словарик (localStorage) с отметками «учу/знаю»
  и счётчиком повторений.
- Горячие клавиши (`Space` — 🎙/отправить, `Esc` — стоп), кнопки у ответа «🔁 Повторить»,
  «🐢 Медленнее», «🎧 Себя» (запись своего варианта через MediaRecorder), озвучка слов 🔊.
- Контроль распознавания: при низкой уверенности STT текст попадает в поле ввода для
  правки (режимы «авто/всегда/никогда»), кнопка «✎ Проверить», `Esc` не теряет текст.
- Защита от «исправлений» шума STT: `filterAsrFixes` выкидывает пары, отличающиеся только
  хамзой/та-марбутой/алиф-максурой/огласовками; если кроме них ничего нет — «✓ Отлично!».
- Любой браузер: серверное распознавание через `/api/transcribe` (PCM → WAV → Gemini
  `input_audio`). Настройка «Распознавание речи»: авто / браузерное / серверное.
- Git-репозиторий: https://github.com/ismail-sketch/arabic-speaker

## Технические заметки

- Ключ и служебные файлы НЕ отдаются браузеру (см. `serveStatic` blocklist).
- Формат ответа модели — метки `AR:` / `RU:` / `FIX:` (парсинг regex в `parseReply`).
- Русский вопрос в FIX не разбирается: модель считает его просьбой о помощи и оставляет FIX пустым.
- STT: `micLang` = `ar` | `ru` (localStorage `ar_miclang`), списки локалей `AR_LANGS` / `RU_LANGS`.
- Живое переключение: `switchLangLive()` делает `commitLocal()` → `engine.abort()` → новый
  движок с новой локалью; `base` сохраняется, `sessionStartLang` помнит исходный язык.
- Итог: `sessionEntries` → `finalizeSession()` (локально: FIX + русские вопросы) → ключ
  `ar_sessions` (до 20 занятий, транскрипт ≤120 реплик); слова сливаются в `ar_vocab`
  (ключ без огласовок и с нормализацией алифов/персидских букв).
- ИИ-разбор: `requestAiSummary()` просит строгий JSON и парсит `extractJson()`;
  проверка формы ответа и защита от кривых полей — в `requestAiSummary`.
- Харакаты: `stripHarakat` убирает диакритику `[\u064B-\u065F\u0670\u06D6-\u06ED]`.
- Кодировка: в `server.js` и тело запроса, и ответ AnyModel читаются через `setEncoding('utf8')`.
  Без этого многобайтные буквы рвутся на границах чанков и превращаются в «?»/«�».
- Текст модели чистится `cleanText` (U+FFFD, управляющие и bidi-символы) и `normalizeArabic`
  (персидские варианты kaf/yeh → арабские, татвиль), иначе в арабском видны «кривые» буквы.
- Арабский шрифт задаётся `--ar-font` (Sakkal Majalla / Traditional Arabic / Noto Naskh / …).
- Запись своего голоса (`toggleSelfRecord`) и STT делят один микрофон: перед записью
  вызывается `stopSession(false)`, после — дорожки освобождаются.
- STT-контроль: в `onresult` копятся `sawFinal`, `confKnown`, `minConf`; `shouldReview()`
  решает, отправить сразу или вызвать `moveToInput()` (текст в `#textIn`, `lastReviewed`).
- `asrKey()` приравнивает неразличимые в STT варианты письма, `filterAsrFixes()` чистит FIX.
- Серверный STT: `startServerSession()` пишет PCM через `ScriptProcessorNode`, `stopServerSession()`
  ресемплит через `OfflineAudioContext` в 16 кГц, нормализует громкость, кодирует WAV и шлёт
  base64 в `/api/transcribe`; сервер передаёт аудио как `input_audio` (до 60 с, до 12 МБ).
  Пока идёт расшифровка — `srvBusy`.
- Аудио в AnyModel принимают не все модели: проверены `gc/gemini-3.1-flash-lite-preview`
  и `ag/gemini-3.8-flash-*`. Порядок контента важен: сначала `text`, потом `input_audio`.
- Сервер проверяет ответ на отказ («не вижу аудио», эхо инструкции) и до 3 раз пробует
  другие модели из `TRANSCRIBE_FALLBACKS`; пустой ответ = тишина.
- Режим `usingServerSTT()`: `server` — всегда; `auto` — сервер, если браузер не Chrome/Edge
  (`likelyGoodBrowserSTT`) или браузерное распознавание уже не сработало (`ar_stt_failed`).
  Плюс сторожевой таймер 3 с в `startEngine` и `fallbackToServer()` при ошибках network.
- Сервер форсирует IPv4 и ретраи (обход `fetch failed` на Windows).

## Известные ограничения

- Браузерное распознавание (Web Speech API) есть только в Chrome/Edge; в Firefox/Safari
  и других браузерах включается серверное распознавание (нужен `ANYMODEL_KEY`).
- Микрофон доступен только на `localhost` или по HTTPS — это ограничение браузеров,
  в том числе для серверного режима.
- Серверное распознавание добавляет задержку (~3–5 с) и расход токенов; запись (до 60 с)
  отправляется в AnyModel.
- Набор моделей и поддержка аудио на шлюзе могут меняться: если распознавание перестало
  работать, проверьте `MODEL_TRANSCRIBE`/`TRANSCRIBE_FALLBACKS` (см. `/api/stt`).
- В серверном режиме язык определяется моделью автоматически; кнопка «Язык» — лишь подсказка.
- Распознавание одним движком = один язык: арабский и русский переключаются вручную,
  автоопределения языка речи нет в браузерном режиме (в серверном язык определяет модель,
  текстовый ввод понимает оба языка сразу).
- Оценка произношения отсутствует (исправляется только распознанный текст).
- Web Speech API не отдаёт внятную уверенность во всех браузерах: если `confidence` не
  приходит, проверка текста срабатывает только по эвристикам (нет финального результата,
  латиница в арабской речи).
- Парсинг ответа regex-метками хрупкий.
- Итоги и словарик лежат только в браузере (localStorage): очистка данных сайта их удалит;
  хранятся последние 20 занятий, при нехватке места транскрипты отбрасываются.
- ИИ-разбор зависит от модели: если она вернёт не JSON, покажется ошибка и можно повторить.

## Следующие фичи (план, по приоритету)

1. **JSON-ответ модели** вместо меток AR/RU/FIX — надёжнее.
2. **Автоотправка по тишине** (порог ~4–5 с) + горячая клавиша.
3. **Повторение по словарику (SRS)**: карточки из `ar_vocab`, интервалы, «учу → знаю».
4. Режим «перевод» (RU → AR), потоковый ответ/перебивание.

## Конвенции

- Русскоязычные комментарии, ключ только через `.env`, без внешних зависимостей,
  UI-тексты на русском, арабский текст — без латиницы.
